# 12 路锁控板测试配置 App（Android）

这是一个 Android App，用于对定昌电子 DC_锁控_12 锁控板（固件 LOCK_12_MODBUS_TIMED_20261006）做完整的功能测试与配置。板卡在同一条 485 总线上同时支持**私有协议**和 **MODBUS RTU**，App 两种协议都支持。

- 厂家协议文档 `12路锁控板私有通讯协议-20261006.pdf`、`12路锁控板MODBUS-RTU协议-20261006.pdf`：**不随仓库分发**，请向厂家索取后放进 `docs/`（已加入忽略列表）。文件指纹见 `docs/协议文档说明-20261006.md`
- `docs/用户手册.md` / `docs/用户手册.pdf`：面向现场操作人员的安装和使用说明（`docs/用户手册.pdf` 为图文版，可运行 `python3 docs/manual/build_manual.py` 重建）
- `docs/协议文档说明-20261006.md`：文档中的矛盾、不清楚之处和协议限制，以及 App 的处理方式
- `docs/设计说明.md`：架构、事务引擎、安全策略、读回清账、测试项
- `docs/真机验收清单.md`：模拟器和单元测试覆盖不到、必须在真机上完成的验收项
- `docs/示例报告-模拟器.txt`：模拟器上一次全部通过的测试报告

目标设备：**Android 11（API 30）**；minSdk 26，targetSdk 36。

## 功能

| 页签 | 内容 |
|---|---|
| 连接 | 4 种链路：USB 转 485（OTG）、板载串口 `/dev/ttyS*`、TCP 串口服务器、内置模拟器；总线扫描地址 1–15，同时探测两种协议的版本 |
| 控制 | 可切换控制协议（私有 / MODBUS）；12 路通道：开锁、读反馈；灯/继电器通道可持续或定时输出；批量操作：逐路开多个、同时开、整体输出、开全部；读回 0004 输出控制字；“逐路关断并读回确认”；现场确认断电 |
| 测试 | T0–T11、M3–M7、X1–X2，覆盖两种协议的脉冲开锁、输出、定时、异常响应和跨协议定时规则；可选人工确认；多板批量测试；报告导出为 TXT/JSON；寿命测试 |
| 终端 | 私有帧构造（自动计算累加校验）、MODBUS 帧构造（自动计算 CRC）、原始 HEX 发送；广播需要二次确认；通讯日志可过滤和导出 |
| 配置 | 查询超时、单路动作最长时间、动作余量、迟到隔离与最长寿命、丢弃发送回显；电控锁允许的最长定时通电；每块板的接线档案；拨码换算；模拟器的动作时序和故障注入 |

## 安全规则

- **持续通电会烧坏电控锁**。会上电的写入，包括私有 0x16/0x1A 和 MODBUS 写 0004/0008，必须同时满足：通道配置为“灯/继电器”，并且本次连接已确认接线档案。电控锁只能在设置的上限内**定时**通电（默认禁止），读回确认关断之前不能重新定时。
- 两类写入一律拒绝：单独写 0005，以及写 0005 却不写 0004。这两种写入会取消所有通道的定时，使原本定时的输出变成一直通电（MODBUS 手册第 13、15 页）。单独写 0007 也拒绝。广播不允许上电。
- 0x16/0x1A 的回复不带通道号，所以 App **只依据读回 0004 来确认关断**。测试结束、停止或断开时，都会逐路关断并读回确认；确认不了的通道标为“可能仍带电”。
- 动作类指令永不自动重试，超时记为“结果未知”。新脉冲任务会替换正在执行的任务，所以 App 会等上一个动作窗口结束后再发下一个脉冲。

## 构建

```bash
source tools-env.sh        # 指向本机共享的 SDK/JDK/Gradle 缓存（JDK 17 的信任库问题已在脚本中处理）
systemd-run --user --scope -p MemoryMax=10G -p MemorySwapMax=0 \
  ./gradlew :core:test :app:testDebugUnitTest :app:lintDebug :app:assembleRelease
```

产物：`app/build/outputs/apk/release/app-release.apk`，包含 armeabi-v7a / arm64-v8a / x86_64 三种 ABI，使用 v2 签名方案（Android 7 及以上，包括 Android 11）。

**签名**：签名密钥**不在仓库里**。release 构建读取本机文件 `~/.android-keys/lock-board-485/signing.properties`（也可以用环境变量 `LOCKBOARD_SIGNING_PROPERTIES` 指定其他路径），文件中包含 `storeFile`、`storePassword`、`keyAlias`、`keyPassword` 四项。正式发布版的证书 SHA-256 为 `06a7d6003fcf557f2733c861c654ca97b1eebf40a60883bb2bfe63a94fc7c77b`。找不到该文件时，只输出未签名的 `app-release-unsigned.apk`。密钥库和密码由维护者另行保管：丢失后无法再发布可以覆盖安装的升级版本。

核对签名：

```bash
$ANDROID_HOME/build-tools/36.0.0/apksigner verify --verbose --print-certs app/build/outputs/apk/release/app-release.apk
```

debug 构建不签名，只用于开发调试；部署请使用 release。

## Android 11 部署注意

- **USB OTG**：首次连接会弹出系统授权框；拔出适配器后链路标记为断开。
- **板载串口**：需要主板固件开放 `/dev/ttyS*` 的读写权限和 SELinux 策略；收发器靠 RTS 换向时，打开“内核 RS485 模式”。
- **TCP**：串口服务器设为 TCP Server 透传，9600 8N1。MODBUS 帧以约 5 ms 的静默分隔，网关不能把一帧拆开或把多帧拼在一起。
- 报告和日志保存在应用私有目录，通过系统分享导出。
